# 1.9 Model Context Protocol (MCP) and Cortex Knowledge Extensions (CKE)

> **Exam Domain:** 1.0 — Snowflake for Gen AI Overview (18%)  
> **Exam Objective:** Understand MCP servers, connectors, and pre-built knowledge extensions

## Model Context Protocol (MCP)

MCP is an **open-source standard** that lets AI agents securely interact with business applications and external data systems. Snowflake supports MCP in three ways:

### 1. Snowflake-Managed MCP Server (Expose Snowflake to External Clients)

Makes Snowflake AI capabilities accessible to external AI agents:

```sql
CREATE OR REPLACE MCP SERVER my_mcp_server
FROM SPECIFICATION $$
tools:
  - tool_spec:
      type: "CORTEX_AGENT_RUN"
      name: "analytics_agent"
  - tool_spec:
      type: "CORTEX_SEARCH_SERVICE_QUERY"
      name: "doc_search"
  - tool_spec:
      type: "SYSTEM_EXECUTE_SQL"
      name: "run_sql"

tool_resources:
  analytics_agent:
    agent: "my_db.my_schema.my_agent"
  doc_search:
    name: "my_db.my_schema.search_service"
  run_sql:
    warehouse: "my_wh"
$$;
```

**Supported tool types:**

| Type | Purpose |
|------|---------|
| `CORTEX_AGENT_RUN` | Expose a Cortex Agent |
| `CORTEX_SEARCH_SERVICE_QUERY` | Expose Cortex Search |
| `CORTEX_ANALYST_MESSAGE` | Expose Cortex Analyst |
| `SYSTEM_EXECUTE_SQL` | Execute SQL queries |
| `GENERIC` | UDFs and stored procedures |

**URL format:**
```
https://<account_url>/api/v2/databases/{db}/schemas/{schema}/mcp-servers/{name}
```

**Authentication:** OAuth 2.0 (Snowflake OAuth or External OAuth)

### 2. MCP Connectors (Connect Agents to External Tools)

Allow Cortex Agents to call **remote MCP servers** (outbound):

```sql
CREATE EXTERNAL MCP SERVER atlassian_mcp
  WITH DISPLAY_NAME = 'Atlassian (Jira & Confluence)'
  URL = 'https://mcp.atlassian.com/v1/mcp'
  API_INTEGRATION = jira_api_integration;
```

**Pre-built connectors available for:** Atlassian Jira, GitHub, Glean, Linear, Salesforce, and custom servers.

### 3. SPCS-Hosted MCP Server (For Native Apps)

```sql
CREATE CUSTOM MCP SERVER services.my_mcp_server
  SERVICE = services.my_service
  ENDPOINT = mcp_endpoint
  PATH = '/mcp';
```

## MCP Access Control

```sql
-- Grant access to MCP server
GRANT USAGE ON MCP SERVER my_db.my_schema.my_mcp_server TO ROLE app_role;

-- Required role
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_AGENT_USER TO ROLE app_role;
```

## Cortex Knowledge Extensions (CKE)

CKEs are **pre-built knowledge packages** available from the Snowflake Marketplace that provide ready-to-use Cortex Search services containing curated, indexed content.

### How CKEs Work

1. Install from Snowflake Marketplace (shared database)
2. Contains pre-built Cortex Search service with indexed content
3. Add to Cortex Agents as a search tool
4. Query directly via SEARCH_PREVIEW for testing

### Example: Snowflake Documentation CKE

```sql
-- Install from Marketplace
CREATE DATABASE IF NOT EXISTS SNOWFLAKE_DOCUMENTATION 
  FROM LISTING 'GZSTZ67BY9OQ4';

-- Query the CKE
SELECT SNOWFLAKE.CORTEX.SEARCH_PREVIEW(
  'SNOWFLAKE_DOCUMENTATION.SHARED.CKE_SNOWFLAKE_DOCS_SERVICE',
  '{"query": "How to create a dynamic table?", 
    "columns": ["CHUNK", "DOCUMENT_TITLE", "SOURCE_URL"], 
    "limit": 5}'
);
```

### Using CKE with Agents

```yaml
tools:
  - tool_spec:
      type: "cortex_search"
      name: "SnowflakeDocs"
      description: "Search official Snowflake documentation"

tool_resources:
  SnowflakeDocs:
    name: "SNOWFLAKE_DOCUMENTATION.SHARED.CKE_SNOWFLAKE_DOCS_SERVICE"
    max_results: "5"
```

### Available CKEs

CKEs are published as Marketplace listings. Common examples:
- Snowflake Documentation
- Industry-specific knowledge bases
- Partner documentation

## Exam Tips

1. **MCP is an open standard** — not Snowflake-proprietary
2. **Three MCP patterns**: Managed (expose Snowflake), Connectors (call external), SPCS (native apps)
3. **OAuth 2.0** authentication for managed MCP servers
4. **CKEs = pre-built search services** from Marketplace
5. **CKE = shared database** with Cortex Search service inside
6. **CORTEX_AGENT_USER** role needed for MCP server usage
7. **CREATE EXTERNAL MCP SERVER** for outbound connections to remote tools
8. **MCP connectors** require API integration (security integration + network rule)
