## Scoring Configuration

Control how results are ranked with `scoring_config`:

```python
response = service.search(
    query="network issues",
    columns=["content", "source"],
    scoring_config={
        "weights": {
            "texts": 1,      # BM25 keyword weight
            "vectors": 4,    # Semantic vector weight
            "reranker": 1    # Neural reranker weight
        }
    },
    limit=10
)
```

### Weight Interpretation

```
┌─────────────────────────────────────────────────┐
│     SCORING PIPELINE (configurable weights)      │
│                                                   │
│  Query ──┬──▶ BM25 Keyword (weight: 1)           │
│          │                                        │
│          ├──▶ Vector Semantic (weight: 4)         │
│          │                                        │
│          └──▶ Reranker (weight: 1)                │
│                                                   │
│  All results combined via Reciprocal Rank Fusion  │
│  adjusted by relative weights                     │
└─────────────────────────────────────────────────┘
```

- Weights are **relative** (1:4:1 = 10:40:10)
- Higher vector weight = more semantic (meaning-based) results
- Higher text weight = more exact-match results
- `"reranker": "none"` disables neural reranking (faster, less accurate)

### Additional Scoring Features

| Feature | Description |
|---------|-------------|
| `numeric_boosts` | Boost by numeric column values |
| `time_decays` | Prefer recent documents |
| `text_boosts` | Boost when text column matches |
| `vector_boosts` | Boost by vector similarity |

## Analytical Search (Preview)

Cortex Agents can perform **corpus-wide analysis** — not just finding single documents, but analyzing patterns across ALL retrieved content:

```
┌─────────────────────────────────────────────────────────┐
│            ANALYTICAL SEARCH FLOW                         │
│                                                           │
│  User: "What are the top 3 complaint themes              │
│         across all our support tickets?"                  │
│                                                           │
│  Agent:                                                   │
│    1. Cortex Search → retrieves relevant tickets          │
│    2. AI_FILTER → filters for actual complaints           │
│    3. AI_EXTRACT → extracts themes per ticket             │
│    4. SQL aggregation → counts and ranks themes           │
│    5. Returns: structured analysis                        │
└─────────────────────────────────────────────────────────┘
```

**Key difference from standard RAG:**
- Standard RAG: "Find me the answer in these docs"
- Analytical Search: "Analyze ALL matching docs and give me insights"

## Agent Skills (SKILL.md)

Packaged, reusable task-specific capabilities for agents:

```yaml
# In agent specification:
tools:
  - tool_spec:
      type: "skill"
      name: "data_quality_checker"
      
tool_resources:
  data_quality_checker:
    stage: "@my_stage/skills/quality_check"
```

Skills are defined in SKILL.md files stored on stages or Git repos, containing:
- Instructions for the agent
- Available tools and resources
- Example interactions

## Semantic View Materializations

Pre-aggregate data for faster query performance:

```sql
CREATE OR ALTER SEMANTIC VIEW my_view
  ...
  MAX_STALENESS = 120  -- minimum 120 seconds
  ...
```

| Aspect | Detail |
|--------|--------|
| **What** | Pre-computed aggregations of dimensions + metrics |
| **When** | Queries via `SEMANTIC_VIEW()` function only |
| **Not for** | Cortex Analyst/Agents (they run physical SQL directly) |
| **Requires** | `MAX_STALENESS` property (min 120 seconds) |
| **Benefits** | Faster query execution for semantic SQL |

> **Exam Tip:** Materializations benefit `SEMANTIC_VIEW()` queries only — NOT Cortex Analyst or Agents.

## Cortex Search + Agents Integration

### Standard Search (Document Retrieval)
```yaml
tools:
  - tool_spec:
      type: "cortex_search"
      name: "DocSearch"
      description: "Find relevant policy documents"
tool_resources:
  DocSearch:
    name: "db.schema.policy_search"
    max_results: "5"
```

### Analytical Search (Corpus Analysis)
The agent combines Search with other tools automatically for corpus-wide analysis when questions require aggregation across many documents.

## Web Search Tool in Agents

Access real-time internet information:

```yaml
tools:
  - tool_spec:
      type: "web_search"
      name: "web_search"
      description: "Search the internet for current information"
```

- Powered by Brave Search API
- Returns real-time results
- Useful for: current events, pricing, documentation updates

## Exam Tips

1. **Scoring weights are relative** — 1:4:1 same as 10:40:10
2. **Analytical Search** = corpus-wide analysis (not just document retrieval)
3. **Materializations** only benefit SEMANTIC_VIEW() queries, NOT Analyst/Agents
4. **Agent Skills** are SKILL.md files on stages/repos
5. **Web search tool** provides real-time internet access to agents
6. **Disable reranker** with `"reranker": "none"` for faster (less accurate) results
