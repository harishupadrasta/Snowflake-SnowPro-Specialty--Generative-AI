## What is Cortex Code?

Cortex Code (CoCo) is Snowflake's **AI-powered development assistant** that helps write, debug, and optimize SQL, Python, and Snowflake configurations. It leverages LLMs running in Snowflake Cortex and respects full RBAC — suggestions are based only on data your role can access.

---

## Deployment Surfaces

| Surface | Description | Billing Service Type | Key Features |
|---------|-------------|---------------------|--------------|
| **Snowsight (Worksheets)** | Inline AI assistant in SQL worksheets | `CORTEX_CODE_SNOWSIGHT` | Chat panel, @auto-complete, Run/Add buttons |
| **Desktop IDE (CoCo Desktop)** | Full standalone application | `CORTEX_CODE_DESKTOP` | Full file system, git, subagents, hooks, plugins |
| **Workspaces (Notebooks)** | AI code suggestions in notebook cells | `CORTEX_CODE_WORKSPACE` | Tab to accept, inline completions |
| **CLI** | Command-line interface | `CORTEX_CODE_CLI` | Same as Desktop, terminal-based |

---

## Key Capabilities

| Capability | Description |
|-----------|-------------|
| **Natural language → SQL** | Type a question, get executable SQL |
| **AI code suggestions** | Inline completions as you type (Tab to accept) — GA July 2026 |
| **Code explanation** | "Explain this query step by step" |
| **Query optimization** | Suggest clustering, filter push-down, CTE refactoring |
| **Debugging** | Identify errors, suggest fixes, explain error messages |
| **Documentation Q&A** | Answer Snowflake feature questions from official docs |
| **Schema exploration** | Discover tables/columns via conversational Q&A |
| **Multi-turn conversation** | Follow-up questions maintain context within a session |
| **Custom instructions** | Up to 2,000 characters of persistent session context |
| **@ schema references** | Type `@table_name` for auto-complete schema suggestions |

---

## Snowsight Behavior

When using Cortex Code in Snowsight worksheets:

1. **Set context first** — Select database + schema before asking questions
2. **Metadata awareness** — CoCo sees your schema (tables, columns, views) but NOT actual data values
3. **Top ~10 tables** — CoCo considers the most relevant tables matching your question (not all)
4. **Response options** — "Run" (execute immediately) or "Add" (insert into worksheet for editing)
5. **New schema delay** — New/altered tables may take up to a few hours to be recognized

## Desktop & CLI Features (CoCo Desktop)

| Feature | Description |
|---------|-------------|
| **Skills** | `.cortex/skills/` or `~/.snowflake/cortex/skills/` — inject domain knowledge via SKILL.md files |
| **Plugins** | Bundles of skills, hooks, and MCP servers — shared via Snowflake catalog |
| **Subagents** | Autonomous agents (explore, generalPurpose, plan) for parallel/complex tasks |
| **Hooks** | Scripts that intercept tool calls (PreToolUse, PostToolUse, UserPromptSubmit) |
| **MCP Servers** | Connect to GitHub, Jira, databases via Model Context Protocol |
| **Background agents** | Up to 50 concurrent agents running in background |
| **Git worktree isolation** | Agents can work in separate branches without conflicts |

## Access Requirements

```sql
-- 1. Grant Cortex Code access in Snowsight (role still named COPILOT_USER)
GRANT DATABASE ROLE SNOWFLAKE.COPILOT_USER TO ROLE developer_role;

-- 2. Cross-region inference MUST be enabled (required for Cortex Code)
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

-- 3. Check current setting
SHOW PARAMETERS LIKE 'CORTEX_ENABLED_CROSS_REGION' IN ACCOUNT;
```

> ⚠️ **Exam Trap:** Cortex Code will NOT work if `CORTEX_ENABLED_CROSS_REGION = 'DISABLED'` (the default). This is different from other Cortex AI functions which work locally without cross-region.

## Billing

| Surface | Service Type | Billing Method |
|---------|-------------|----------------|
| Snowsight worksheets | `CORTEX_CODE_SNOWSIGHT` | Per token (input + output) |
| Desktop / CLI | `CORTEX_CODE_CLI` or `CORTEX_CODE_DESKTOP` | Per token (input + output) |
| Workspaces (notebooks) | `CORTEX_CODE_WORKSPACE` | Per token (input + output) |

Track usage:
```sql
SELECT * FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
WHERE SERVICE_TYPE LIKE 'CORTEX_CODE%';
```

## Cortex Code vs CoWork vs Cortex Agents

| Aspect | Cortex Code | CoWork | Cortex Agents |
|--------|-------------|--------|---------------|
| **Audience** | Developers | Business users | End users (via app) |
| **Interface** | IDE / Worksheet / CLI | Chat in Snowsight | SQL function / REST API |
| **Purpose** | Write code | Explore data | Orchestrate tools |
| **Requires** | COPILOT_USER + cross-region | CORTEX_USER or CORTEX_AGENT_USER | CORTEX_AGENT_USER |
| **Creates** | SQL/Python code | Answers + charts | Responses via tool calls |
| **Data access** | Metadata only (no values) | Via configured agents | Via tools (Search, Analyst) |

---

## Exam Tips

1. **Requires cross-region inference** — won't work with `DISABLED` (unlike other AI functions)
2. **Four surfaces**: Snowsight, Desktop, CLI, Workspaces (notebooks)
3. **Separate billing** — each surface has its own SERVICE_TYPE
4. **COPILOT_USER role** needed for Snowsight access (legacy name, still the actual role)
5. **Not the same as Cortex Agents** — Code assists developers, Agents serve end users
6. **No data value access** — CoCo sees schema/metadata only, not actual row data
7. **Custom instructions** — 2,000 characters max, persist within a session
8. **AI code suggestions** — Tab to accept (changed from Shift+Enter, GA July 2026)
9. **Skills are markdown** — SKILL.md files in `.cortex/skills/` directories
10. **MCP servers** — configured in `~/.snowflake/cortex/mcp.json`
