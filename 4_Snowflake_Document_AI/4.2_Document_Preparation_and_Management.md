# 4.2 Document Preparation and Management

> **Exam Domain:** 4.0 — Snowflake Document Processing (15%)  
> **Exam Objective:** Properly stage and manage documents for AI processing

---

## Stage Requirements

AI functions that process files require specific stage configurations:

```sql
-- Internal stage (recommended)
CREATE OR REPLACE STAGE doc_stage
  DIRECTORY = (ENABLE = TRUE)
  ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE');

-- External stage (S3 example)
CREATE OR REPLACE STAGE external_docs
  STORAGE_INTEGRATION = my_s3_integration
  URL = 's3://my-bucket/documents/'
  DIRECTORY = (ENABLE = TRUE)
  ENCRYPTION = (TYPE = 'AWS_SSE_S3');
```

### Stage Rules (Exam-Critical)

| Requirement | Detail |
|-------------|--------|
| **Encryption** | Must be server-side (SNOWFLAKE_SSE or AWS_SSE_S3) |
| **NOT supported** | SNOWFLAKE_FULL encryption |
| **NOT supported** | User stages, table stages |
| **NOT supported** | Customer-side encryption (AWS_CSE, AZURE_CSE) |
| **NOT supported** | Double-quoted stage names |
| **Directory table** | Required for DIRECTORY() queries |
| **AUTO_REFRESH** | Set TRUE for external stages with new files |

## Working with Files

### Upload Files

```sql
-- Upload via Snowsight or SnowSQL
PUT file:///path/to/document.pdf @doc_stage;
```

### List Files

```sql
-- Using directory table
SELECT * FROM DIRECTORY(@doc_stage);

-- Returns: RELATIVE_PATH, SIZE, LAST_MODIFIED, ETAG, etc.
```

### Create File References

```sql
-- Single file
SELECT TO_FILE('@doc_stage', 'invoice.pdf');

-- Table of all files
CREATE TABLE my_files AS
SELECT 
    RELATIVE_PATH,
    TO_FILE('@doc_stage', RELATIVE_PATH) AS file_ref,
    SIZE
FROM DIRECTORY(@doc_stage)
WHERE RELATIVE_PATH LIKE '%.pdf';
```

## FILE Data Type

The FILE type represents a reference/pointer to a staged file containing metadata:

```sql
CREATE TABLE documents (
    doc_id INT AUTOINCREMENT,
    file_ref FILE,          -- FILE data type
    uploaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP()
);

INSERT INTO documents (file_ref)
SELECT TO_FILE('@doc_stage', RELATIVE_PATH)
FROM DIRECTORY(@doc_stage);
```

### FILE Object Fields

| Field | Description |
|-------|-------------|
| `RELATIVE_PATH` | Path to file within the stage |
| `STAGE` | Stage where file resides (e.g., `@MY_STAGE`) |
| `SIZE` | File size in bytes |
| `CONTENT_TYPE` | MIME type (e.g., `application/pdf`, `image/png`) |
| `ETAG` | Entity tag for change detection |
| `LAST_MODIFIED` | Last modification timestamp |

### Helper Functions for FILE

```sql
-- Extract the relative path from a FILE object
SELECT FL_GET_RELATIVE_PATH(file_ref) AS filename FROM documents;

-- Extract the stage name
SELECT FL_GET_STAGE(file_ref) AS stage_name FROM documents;
```

## Text Chunking for RAG

After parsing documents, chunk the text for embedding:

```sql
-- Parse then chunk
WITH parsed AS (
    SELECT 
        RELATIVE_PATH,
        AI_PARSE_DOCUMENT(TO_FILE('@docs', RELATIVE_PATH), {'mode': 'LAYOUT'}):content AS content
    FROM DIRECTORY(@docs)
    WHERE RELATIVE_PATH LIKE '%.pdf'
)
SELECT 
    RELATIVE_PATH,
    chunk.VALUE::STRING AS chunk_text
FROM parsed,
LATERAL FLATTEN(
    SPLIT_TEXT_RECURSIVE_CHARACTER(content, 'snowflake-arctic-embed-m-v1.5', {'max_tokens': 512, 'overlap': 50})
) AS chunk;
```

## Exam Tips

1. **SNOWFLAKE_SSE** or **AWS_SSE_S3** encryption required
2. **User stages and table stages NOT supported**
3. **SNOWFLAKE_FULL encryption NOT supported** (it's client-side)
4. **DIRECTORY = TRUE** needed for DIRECTORY() table function
5. **TO_FILE** creates FILE references from stage + path
6. **FILE data type** can be stored in tables
7. **FL_GET_RELATIVE_PATH** extracts filename from FILE object
8. **Split after parsing** — use SPLIT_TEXT_RECURSIVE_CHARACTER for chunking
