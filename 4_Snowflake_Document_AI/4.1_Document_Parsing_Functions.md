# 4.1 Document Parsing Functions

> **Exam Domain:** 4.0 — Snowflake Document Processing (15%)  
> **Exam Objective:** Use AI_PARSE_DOCUMENT and AI_EXTRACT for document intelligence

---

> 📘 **Key Terms**
>
> | Term | Definition |
> |------|-----------|
> | **OCR** | Optical Character Recognition — extracting text from images/scans |
> | **LAYOUT mode** | Preserves document structure (tables, headers, paragraphs) |
> | **FILE data type** | Snowflake type referencing files on stages |
> | **Document AI** | Snowflake's feature for AI-powered document extraction |
> | **arctic-extract** | Fine-tunable extraction model |
>
> *See full [Glossary](../GLOSSARY.md)*

## AI_PARSE_DOCUMENT

Extracts text and structure from documents (PDF, images, Office files).

### Syntax

```sql
AI_PARSE_DOCUMENT(
    <file>,
    <options>
)
```

### Modes

| Mode | Description | Output |
|------|-------------|--------|
| `OCR` | Optical character recognition (text only) | Plain text |
| `LAYOUT` | Preserves document structure (tables, headers, lists) | Structured markdown |

```sql
-- OCR mode (fastest, text only)
SELECT AI_PARSE_DOCUMENT(
    TO_FILE('@docs', 'invoice.pdf'),
    {'mode': 'OCR'}
):content AS text_content;

-- LAYOUT mode (preserves structure)
SELECT AI_PARSE_DOCUMENT(
    TO_FILE('@docs', 'invoice.pdf'),
    {'mode': 'LAYOUT'}
):content AS structured_content;
```

### Options

| Option | Type | Description |
|--------|------|-------------|
| `mode` | STRING | `'OCR'` or `'LAYOUT'` |
| `page_limit` | INT | Max pages to process |
| `page_split` | BOOLEAN | Return array of per-page results |

```sql
-- Process first 5 pages, split by page
SELECT AI_PARSE_DOCUMENT(
    TO_FILE('@docs', 'long_report.pdf'),
    {'mode': 'LAYOUT', 'page_limit': 5, 'page_split': TRUE}
) AS pages;
```

### Response Structure

```json
{
    "content": "Extracted text/markdown...",
    "pages": [
        {"page_number": 1, "content": "Page 1 text..."},
        {"page_number": 2, "content": "Page 2 text..."}
    ],
    "metadata": {
        "page_count": 10,
        "format": "pdf"
    }
}
```

## AI_EXTRACT for Documents

Extract structured data from documents into JSON:

```sql
SELECT AI_EXTRACT(
    TO_FILE('@invoices', 'invoice_001.pdf'),
    {
        'vendor_name': 'string',
        'invoice_number': 'string',
        'total_amount': 'number',
        'date': 'string',
        'line_items': 'array'
    }
) AS extracted_data;
```

---

## Supported File Types

| Type | Extensions |
|------|-----------|
| PDF | .pdf |
| Images | .jpg, .jpeg, .png, .gif, .bmp, .tiff, .webp |
| Microsoft Office | .docx, .pptx, .xlsx |
| Text | .txt, .csv, .html |

---

## Billing

- **Per page**: 970 tokens per page (both modes)
- Both input and output tokens counted for AI_EXTRACT
- **AI_EXTRACT responseFormat/schema** counts as **input tokens** (billed per row)
- `page_limit` controls costs for large documents
- Cost is same whether OCR or LAYOUT mode

## Document AI (Snowsight Pipeline Feature)

Document AI is a **separate Snowsight UI-based feature** for building document extraction pipelines with a visual interface. It is distinct from `AI_PARSE_DOCUMENT` (which is a SQL function).

### Document AI Privileges (Exam-Critical)

```sql
USE ROLE ACCOUNTADMIN;

-- 1. Database role for Document AI access
GRANT DATABASE ROLE SNOWFLAKE.DOCUMENT_INTELLIGENCE_CREATOR TO ROLE doc_ai_role;

-- 2. Create document intelligence objects in a schema
GRANT CREATE SNOWFLAKE.ML.DOCUMENT_INTELLIGENCE ON SCHEMA db.schema TO ROLE doc_ai_role;

-- 3. Create model (required since March 2025)
GRANT CREATE MODEL ON SCHEMA db.schema TO ROLE doc_ai_role;

-- Also needed:
GRANT USAGE ON WAREHOUSE doc_wh TO ROLE doc_ai_role;
GRANT USAGE ON DATABASE db TO ROLE doc_ai_role;
GRANT USAGE ON SCHEMA db.schema TO ROLE doc_ai_role;
GRANT CREATE STAGE ON SCHEMA db.schema TO ROLE doc_ai_role;
```

### Key Document AI Facts

> ⚠️ **Document AI (Snowsight UI + !PREDICT method) was decommissioned March 16, 2026.** It has been replaced by `AI_EXTRACT`. The exam may still test knowledge of what Document AI *was* and what replaced it.

| Fact | Detail |
|------|--------|
| **Foundation model** | Arctic-TILT → now powers `arctic-extract` in AI_EXTRACT |
| **Decommission date** | March 16, 2026 |
| **Replacement** | `AI_EXTRACT` function (single-step, no model build needed) |
| **Legacy migration** | Migrate models to Model Registry → use `AI_EXTRACT` with `model =>` parameter |
| **Schema privilege** | `CREATE SNOWFLAKE.ML.DOCUMENT_INTELLIGENCE` (legacy — no longer needed for new work) |
| **Current requirement** | Standard `SNOWFLAKE.CORTEX_USER` role for AI_EXTRACT |

### Document Limits (Exam-Critical)

| Function | Max Pages | Max File Size | Supported Formats |
|----------|-----------|---------------|-------------------|
| **AI_PARSE_DOCUMENT** | 2,000 pages | 100 MB | PDF, PPTX, DOCX, JPEG/JPG, PNG, TIFF/TIF, HTML, TXT |
| **AI_EXTRACT** | 125 pages | 100 MB | PDF, PNG, PPTX/PPT, EML, DOC/DOCX, JPEG/JPG, HTM/HTML, TXT, TIF/TIFF, BMP, GIF, WEBP, MD |

### Document AI Decommission (March 2026)

> ⚠️ **Critical Update:** The Document AI UI and `!PREDICT` method were **decommissioned on March 16, 2026**. All extraction now uses `AI_EXTRACT` with the `arctic-extract` model.

| Before (Decommissioned) | After (Current) |
|--------------------------|-----------------|
| Create model build in Document AI UI | Use `AI_EXTRACT` directly — no model build needed |
| Fine-tune in Snowsight UI | Fine-tune arctic-extract via `FINETUNE` + Dataset objects |
| Call `<model>!PREDICT(file)` | Call `AI_EXTRACT(file => ..., responseFormat => ...)` |
| DOCUMENT_INTELLIGENCE_CREATOR role | CORTEX_USER role (standard) |

### AI_EXTRACT Model: arctic-extract

| Fact | Detail |
|------|--------|
| **Foundation model** | Arctic-TILT (proprietary vision-based LLM for document understanding) |
| **Function name** | AI_EXTRACT |
| **Zero-shot capable** | Works without fine-tuning on new document types |
| **Extraction types** | Entity (single values), List (arrays), Table (columns) — all in one call |
| **Max questions per call** | 100 entity + 10 table (1 table question = 10 entity questions) |
| **Output token limit** | 512 tokens/entity, 4096 tokens/table |
| **Scores available** | `scores => TRUE` returns confidence (0–1) per field |
| **Fine-tuning** | Use `FINETUNE` with Dataset objects for custom models |
| **scale_factor** | 1.0–4.0 for enhanced OCR quality on dense/small text |

> **Exam Tip:** This is NOT the same as `AI_PARSE_DOCUMENT`. Document AI is a visual pipeline builder in Snowsight. `AI_PARSE_DOCUMENT` is a SQL function. Both may appear on the exam.

## Exam Tips

1. **Two modes for AI_PARSE_DOCUMENT**: OCR (text only, faster) vs LAYOUT (structure preserved)
2. **LAYOUT mode** returns markdown-like structured content
3. **page_limit** controls how many pages are processed (cost control)
4. **page_split = TRUE** returns array of per-page results
5. **970 tokens per page** billing
6. **TO_FILE required** — documents must be on staged with SSE encryption
7. **AI_EXTRACT** on documents extracts specific fields into JSON schema
8. **Supported**: PDF, images, Office files (docx, pptx, xlsx)
9. **Document AI** (Snowsight) requires `DOCUMENT_INTELLIGENCE_CREATOR` role + `CREATE SNOWFLAKE.ML.DOCUMENT_INTELLIGENCE` + `CREATE MODEL`
10. **Even ACCOUNTADMIN** needs `DOCUMENT_INTELLIGENCE_CREATOR` explicitly granted
