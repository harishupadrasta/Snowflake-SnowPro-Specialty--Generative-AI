# 4.4 Troubleshooting and Optimization

> **Exam Domain:** 4.0 — Snowflake Document Processing (15%)  
> **Exam Objective:** Diagnose and resolve common document processing issues

---

## Common Errors

| Error Message | Cause | Fix |
|---------------|-------|-----|
| `invalid image path` | File doesn't exist or unsupported format | Check path (case-sensitive), verify file extension |
| `Error in secure object` | Stage doesn't exist or not accessible | Verify stage name, use `@` prefix |
| `unsupported image format` | Wrong file type for model | Use supported formats (JPEG, PNG, WEBP, GIF) |
| `Image data exceeds the limit` | File too large | Reduce file size (<10MB for most models) |
| `unknown model` | Model not available in region | Enable cross-region inference |
| `insufficient privileges` | Missing role grants | Grant CORTEX_USER or AI_FUNCTIONS_USER |

---

## Stage-Related Issues

| Issue | Solution |
|-------|----------|
| **SNOWFLAKE_FULL encryption** | Change to SNOWFLAKE_SSE |
| **User/table stage** | Move to named internal/external stage |
| **Customer-side encryption (CSE)** | Use server-side encryption (SSE) |
| **Double-quoted stage name** | Rename stage without quotes |
| **File not found** | Filenames are CASE-SENSITIVE |
| **Directory not enabled** | `ALTER STAGE SET DIRECTORY = (ENABLE = TRUE)` |

## Performance Optimization

### Cost Control

```sql
-- Use page_limit for large documents
SELECT AI_PARSE_DOCUMENT(
    TO_FILE('@docs', 'huge_report.pdf'),
    {'mode': 'OCR', 'page_limit': 10}
);

-- Estimate cost before processing all files
SELECT 
    COUNT(*) AS file_count,
    SUM(SIZE) / 1024 / 1024 AS total_mb
FROM DIRECTORY(@doc_stage);
```

### Throughput Optimization

1. **Use MEDIUM warehouse** (larger doesn't help AI functions)
2. **Batch with LIMIT** during development
3. **Use TRY_COMPLETE** for bulk processing (individual failures don't stop batch)
4. **OCR mode** is faster than LAYOUT if you don't need structure
5. **page_limit** — only process pages you need
6. **Incremental processing** — use streams/tasks to avoid reprocessing

### Choosing the Right Mode

| Use Case | Mode | Why |
|----------|------|-----|
| Simple text extraction | OCR | Fastest, cheapest |
| Tables and structured data | LAYOUT | Preserves table structure |
| Forms with fields | LAYOUT + AI_EXTRACT | Structure + schema extraction |
| Large document summaries | OCR + SUMMARIZE | Don't need structure for summary |

## Error Handling in Pipelines

```sql
-- Use return_error_details for batch robustness
SELECT
    RELATIVE_PATH,
    AI_PARSE_DOCUMENT(
        TO_FILE('@docs', RELATIVE_PATH),
        {'mode': 'OCR'},
        return_error_details => TRUE
    ) AS result
FROM DIRECTORY(@docs)
WHERE RELATIVE_PATH LIKE '%.pdf';

-- result.value = parsed content (NULL on error)
-- result.error = error message (NULL on success)
```

## Exam Tips

1. **Filenames are case-sensitive** — most common "file not found" cause
2. **SNOWFLAKE_SSE** required — SNOWFLAKE_FULL won't work
3. **OCR is faster** than LAYOUT (same token cost per page — both 970 tokens)
4. **page_limit** controls cost for large documents
5. **return_error_details = TRUE** for pipeline robustness
6. **MEDIUM warehouse max** — larger doesn't improve performance
7. **TRY_COMPLETE** for batch error tolerance
8. **Custom network policies** incompatible with AI functions currently
