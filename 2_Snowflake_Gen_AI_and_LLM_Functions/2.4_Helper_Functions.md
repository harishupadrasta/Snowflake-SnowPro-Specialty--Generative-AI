# 2.4 Helper Functions

> **Exam Domain:** 2.0 — Snowflake Gen AI Functions (38%)  
> **Exam Objective:** Understand utility functions that support AI workflows

---

## AI_COUNT_TOKENS

Estimates token count for a given text and model:

```sql
SELECT AI_COUNT_TOKENS('llama3.1-70b', 'This is a test sentence.');
-- Returns: 7

-- Estimate cost before processing
SELECT 
    text_column,
    AI_COUNT_TOKENS('llama3.1-70b', text_column) AS tokens,
    AI_COUNT_TOKENS('llama3.1-70b', text_column) / 1000000.0 * <credit_rate> AS est_credits
FROM my_table;
```

**Key facts:**
- Only compute cost (no token-based charges)
- Model-specific tokenization (different models may count differently)
- Use to estimate costs BEFORE running expensive AI_COMPLETE calls

## SPLIT_TEXT_RECURSIVE_CHARACTER

Splits text into chunks for embedding/RAG pipelines:

```sql
SELECT SPLIT_TEXT_RECURSIVE_CHARACTER(
    long_document_text,
    'snowflake-arctic-embed-m-v1.5',  -- model (determines token counting)
    {'max_tokens': 512, 'overlap': 50}
) AS chunks;
-- Returns: ARRAY of text chunks
```

**Parameters:**
| Parameter | Description |
|-----------|-------------|
| `max_tokens` | Maximum tokens per chunk |
| `overlap` | Token overlap between consecutive chunks |

**Use case:** Preparing documents for Cortex Search or embedding storage.

## SPLIT_TEXT_MARKDOWN_HEADER

Splits markdown documents by header structure:

```sql
SELECT SPLIT_TEXT_MARKDOWN_HEADER(
    markdown_content,
    {'max_tokens': 512}
) AS sections;
-- Returns: ARRAY of sections split at markdown headers
```

**Key facts:**
- Respects markdown header hierarchy (# , ## , ###)
- Keeps headers with their content
- Good for documentation and knowledge base chunking

## TO_FILE

Creates a FILE reference to a staged file for AI functions:

```sql
-- Reference a single file
SELECT TO_FILE('@my_stage', 'document.pdf');

-- Use in AI functions
SELECT AI_COMPLETE(
    'claude-sonnet-4-6',
    'Summarize this document',
    TO_FILE('@docs_stage', 'report.pdf')
);

-- Create a table of file references
CREATE TABLE my_files AS
SELECT TO_FILE('@my_stage', RELATIVE_PATH) AS file_ref
FROM DIRECTORY(@my_stage);
```

**Key facts:**
- Required for all file-based AI functions
- Stage must have server-side encryption (SNOWFLAKE_SSE or AWS_SSE_S3)
- Stage must have directory table enabled for DIRECTORY() queries
- Filenames are case-sensitive
- Cannot use: user stages, table stages, SNOWFLAKE_FULL encryption, double-quoted stage names

## PROMPT

Builds prompt objects with multiple file references:

```sql
-- Compare two images
SELECT AI_COMPLETE(
    'claude-sonnet-4-6',
    PROMPT(
        'Compare image {0} with image {1} and describe differences',
        TO_FILE('@images', 'before.jpg'),
        TO_FILE('@images', 'after.jpg')
    )
);

-- Mix text and files
SELECT AI_COMPLETE(
    'gemini-3.1-pro',
    PROMPT(
        'Given this audio {0}, extract the main topics discussed',
        TO_FILE('@audio', 'meeting.mp3')
    )
);
```

**Key facts:**
- Placeholders: `{0}`, `{1}`, `{2}`, etc.
- Supports mixing text with multiple file references
- Required for multi-file prompts (images, audio, video)

## TRY_COMPLETE

Error-safe version of AI_COMPLETE (returns NULL instead of failing):

```sql
-- Batch processing that won't fail on individual row errors
SELECT 
    id,
    TRY_COMPLETE('llama3.1-70b', text_column) AS result
FROM large_table;
-- Rows that would error return NULL instead of failing the query
```

**Key facts:**
- Same syntax as SNOWFLAKE.CORTEX.COMPLETE
- Returns NULL on error (query continues)
- Use for batch processing large tables
- Legacy namespace: `SNOWFLAKE.CORTEX.TRY_COMPLETE`

## Summary Table

| Function | Purpose | Returns |
|----------|---------|---------|
| AI_COUNT_TOKENS | Estimate token count | INTEGER |
| SPLIT_TEXT_RECURSIVE_CHARACTER | Chunk text by tokens | ARRAY |
| SPLIT_TEXT_MARKDOWN_HEADER | Chunk markdown by headers | ARRAY |
| TO_FILE | Reference staged file | FILE object |
| PROMPT | Build multi-file prompt | Prompt object |
| TRY_COMPLETE | Error-safe completion | VARCHAR or NULL |

---

## Exam Tips

1. **AI_COUNT_TOKENS** — no token-based charges (only compute)
2. **SPLIT_TEXT_RECURSIVE_CHARACTER** — use for RAG chunking pipelines
3. **TO_FILE** requires SSE encryption on the stage
4. **PROMPT** uses `{0}`, `{1}` placeholders for files
5. **TRY_COMPLETE** = batch-safe (NULL on error, query continues)
6. **overlap parameter** in SPLIT_TEXT ensures context continuity between chunks
7. **TO_FILE cannot use** user stages, table stages, or SNOWFLAKE_FULL encryption
