# 2.9 Performance and Model Selection

> **Exam Domain:** 2.0 — Snowflake Gen AI Functions (38%)  
> **Exam Objective:** Select appropriate models and optimize AI function performance

---

## Model Selection Guide

| Need | Recommended Model | Why |
|------|-------------------|-----|
| Highest quality reasoning | claude-sonnet-4-6, deepseek-r1 | Best reasoning capability |
| General purpose (good balance) | llama3.3-70b, mistral-large2 | Quality + speed |
| Fast/cheap for simple tasks | llama3.1-8b, mistral-7b | Lowest cost, fastest |
| Multimodal (images) | claude-sonnet-4-6, llama4-maverick | Vision support |
| Audio/video processing | gemini-3.1-pro | Largest multimodal context |
| Code generation | deepseek-r1, claude-sonnet-4-6 | Specialized reasoning |
| Embeddings (English) | snowflake-arctic-embed-m-v1.5 | Default, good quality |
| Embeddings (multilingual) | snowflake-arctic-embed-l-v2.0 | 1024 dimensions |
| Long documents | snowflake-arctic-embed-l-v2.0-8k | 8K token context |

---

## Warehouse Sizing

> **Critical Exam Fact:** Use **MEDIUM or smaller** warehouse for AI Functions. Larger warehouses do NOT improve AI function performance.

| Warehouse Size | Effect on AI Functions |
|----------------|----------------------|
| XS / S / M | Normal performance |
| L / XL / 2XL+ | Same performance, higher cost |

**Why:** AI functions use serverless compute behind the scenes. The warehouse only manages the SQL query execution, not the model inference.

---

## Cost Optimization Strategies

1. **Use smallest effective model** — llama3.1-8b for classification, llama3.3-70b for complex reasoning
2. **Limit output with max_tokens** — don't generate more than needed
3. **Set temperature = 0** — deterministic output, potentially fewer retries
4. **Batch with LIMIT during development** — test on 10 rows before 10M
5. **Use AI_COUNT_TOKENS** to estimate costs before full runs
6. **Use task-specific functions** — AI_SENTIMENT is cheaper than AI_COMPLETE for sentiment
7. **Cache results** — store AI outputs in tables, don't recompute
8. **Use TRY_COMPLETE** — avoid re-running failed batch queries

---

## Token Estimation

```sql
-- Estimate cost before processing
SELECT 
    COUNT(*) AS row_count,
    SUM(AI_COUNT_TOKENS('llama3.1-70b', text_column)) AS total_input_tokens,
    total_input_tokens / 1000000.0 AS millions_of_tokens
FROM my_table;
```

## Model Lifecycle

| Status | Meaning |
|--------|---------|
| Private Preview | Limited access, subject to change |
| Public Preview | Available to all, may have limitations |
| Generally Available (GA) | Production-ready, SLA-backed |
| Legacy | Deprecated, 60-day notice before removal |
| End of Life (EOL) | Removed from service |

> **Exam Tip:** GA models get 60-day deprecation notice. Preview models have no such guarantee.

---

## Provisioned Throughput

For high-volume, predictable workloads:

- Reserved capacity for specific models
- Guaranteed throughput (tokens per second)
- Predictable costs (fixed rate vs per-token)
- Monitor via `CORTEX_PROVISIONED_THROUGHPUT_USAGE_HISTORY`

---

## REST API vs SQL API Latency

| Method | Latency | Best For |
|--------|---------|----------|
| **Cortex REST API** | Lower latency (direct HTTP) | Real-time applications, chatbots |
| **SQL API** (via session.sql) | Higher latency (SQL parsing overhead) | Batch processing, data pipelines |

> **Exam Tip:** Use the REST API for lower-latency inference in production applications. The SQL API adds query planning/compilation overhead.

---

## Exam Tips

1. **MEDIUM warehouse max** for AI functions — bigger doesn't help
2. **REST API has lower latency** than SQL API for inference
3. **Cost scales with tokens** — shorter prompts = lower cost
4. **Task-specific functions** (AI_SENTIMENT, AI_CLASSIFY) are cheaper than AI_COMPLETE for their task
5. **Temperature 0** for deterministic results and structured output
6. **AI_COUNT_TOKENS** has no token charges (only compute)
7. **GA models** get 60 days deprecation notice
8. **Provisioned throughput** for predictable high-volume workloads
9. **Cache AI results** in tables — don't reprocess unchanged data
10. **Structured output (JSON schema)** may increase latency slightly due to token validation
